# 导出与实际浏览器验证

最终资产：`asset-manifest.json` 中的 GLB 与 SHA-256。Khronos glTF Validator 2.0.0-dev.3.10：**两份 GLB 都是 0 errors / 0 warnings**。店铺的 5 个 info 都是保留的 `ANCHOR_*` 空节点，不是损坏的材质或模型；角色没有 info。

Babylon.js 9.25.0 在实际 headed Chrome 152.0.7977.82 中加载两份资产。GPU 报告：`ANGLE (AMD, ANGLE Metal Renderer: AMD Radeon Pro 555, Unspecified Version)`；没有 SwiftShader。两份素材的资源与脚本加载错误为 0。

- 原始 GLB 导入的 X 反射已用定位空节点实测和补偿。右侧、柜台与 NPC 锚点符合文档，招牌文字方向实际可读。
- 12 条入口至柜台前方的几何射线全部无遮挡：X = −0.73 / 0 / +0.73；Y = 0.3 / 1.0 / 1.68 / 2.55 m。Z = −0.1 至 2.85 m。吊灯原来的干涉已修复。

## 持续性能（不录像）

条件：物理面板 2880×1800；受控浏览器视口 1280×800、DPR 2；预览器缩放上限 1.5；2048 阴影贴图、PCF medium；普通中性光、ACES。每段旋转先预热 3 秒，再连续采样 15 秒。以下是 requestAnimationFrame 时间间隔，不是 GPU timer query。采样时没有录像、截图读回或离线渲染。

| 情景 | 渲染分辨率 | 中位帧时 | P95 | P99 |
|---|---|---:|---:|---:|
| 店铺持续旋转 | 1920×1200 | 16.7 ms | 17.7 ms | 18.0 ms |
| 店铺持续旋转 | 1280×800 | 16.7 ms | 17.6 ms | 18.0 ms |
| 从门口向柜台移动 | 1280×800 | 16.7 ms | 17.6 ms | 18.1 ms |

山墙与封檐缺口已在最后的侧面检查后修复，并重新导出、录制与测量。原始样本数与详细设置见 `evidence/performance-no-recording.json`。**这不是完整游戏、整条街区或其他机器的 FPS 承诺。**角色预览地面已对齐脚底，修正悬空阴影。

录像使用 Chrome canvas captureStream / MediaRecorder VP9，会造成显著的 GPU 画布读取和编码开销。`browser-hardware.json` 的录像期间帧时明显较高，仅用于记录录像条件，不能替代上表；不隐去该差异。

## 视觉上仍可改进

- 店铺重复木纹与屋瓦阵列仍有程序化感；远距离小字会变细，玻璃缺少真实环境反射。
- 角色背面发型、肩肘过渡、背部围裙系带、手部姿态与表情细节仍值得专业精修；材质以常量色为主。
- 室内没有烘焙间接光；预览不能替代 Sol 在正式街景灯光下的检查。
- 没有执行真实玩家碰撞、游戏交互或 NHK 回归。

因此，该验证确认“可导入、可运行、有硬件证据和可编辑源”，不替代最终高质量美术签收。
