# Phone-only gentle teacher correction

User feedback: acknowledging familiarity with 農林水産省 led abruptly into a price story; some voice replies were long, difficult and fast. This is a repair of continuity and assistance, not a new course/mode.

Ordinary next-turn planning intentionally omits article text and title. The active utterance, learner meaning and bounded recent conversation are the basis. Article reference is included only when the learner explicitly asks about its contents. Keyword topic preview stays local; switching topic remains an explicit learner action.

A detached TEXT plan contains one short spoken sentence (or acknowledgement + one short prompt), capped at 48 characters and two sentences/one question, plus optional small scaffolds. Mechanical validation occurs BEFORE audio. Selected abrupt pricing/policy intrusions and abstract-language patterns are rejected unless introduced in the current exchange. This is not a guarantee of complete semantic correctness or JLPT level. Invalid/timed-out drafts use a small same-thread fallback, never a long unvalidated answer. The voice receives only the accepted short text, not the article. Existing realtime model and server credentials are unchanged.

Actual session output speed defaults to 0.80. Slow control sets 0.70 and replays the same utterance, retained during topic change and transport renewal. Simplify control changes the current prompt, not the topic. Both spoken controls and phone buttons are supported. Unexpected verbose audio has a client emergency stop, not an unlimited monologue. This is best effort; speech playback is not a pre-audited recording.

The content plan and its scaffolds are generated together when possible, replacing the old voice-plus-separate-hint flow. First prompts, replay and cached help remain direct short-script audio. Planning adds latency before free replies; measure it honestly, do not claim zero delay. No new model, secret, database, quota or telemetry writes. Existing default-off local UX observations, study storage, backups, TTS/review and historical game remain untouched.

Acceptance must include the reported institution/yes regression, subsequent same-thread simplification, actual API speed acceptance, long-text rejection, stale completion cancellation, phone layout, multiple turns, topic switching, renewal and close. Synthetic audio and phone emulation are labelled as such, not claimed to be human/iPhone or language-learning proof.
