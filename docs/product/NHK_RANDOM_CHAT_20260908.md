# Mobile NHK random simple chat — implementation candidate

User approved changing the overly rigid three-turn pilot and fixing the false quota message. Only phone portrait interaction is in scope. Do not run desktop exploration/browser work for this change.

Local candidate topics are drawn without replacement until the deck is exhausted; a new deck avoids immediate repetition. There is no API call or microphone before Start. This is a curated topic pool matched to the article, NOT infinitely many AI-generated topics. Personal and hypothetical questions are clearly distinguished from article assertions. Conversation responses are adaptive to the learner, use short Japanese, allow Chinese support and yes/no, and do not end after three turns. Help uses the last actual question. In-call shuffle clears topic history and coalesces quick taps while reusing the existing peer and microphone. Reference examples disappear after the first answer because they are not answers to future questions. Actual generated speech transcript is shown.

WebRTC still has a bounded 110-second backend lease because the hosting worker cannot be trusted to run forever. The frontend renews transport before expiry while preserving the current topic and bounded in-memory history, reusing the microphone. There may be a short reconnection pause. Sixty seconds of silence pauses and closes the mic; backgrounding, dismissal, errors and end close it immediately. No learner audio, transcript, score or new learning schema is persisted.

Replace the two-starts-per-two-minutes gate. Keep abnormal-traffic and cost guards: 12 connection creations/minute/client, 60/hour/client, 120/day for the app, 32 responses and 30k accounted tokens per backend segment. These are not user-visible exercise counts, not a precise currency budget, not free unlimited OpenAI usage, and not user-account authorization. Shuffle does not spend a connection quota. Explain app throttling, app usage guard, provider rate limits and provider insufficient quota separately. This remains a personal pilot; individual account authentication remains a prerequisite to wider public release.

Existing server speech/TTS, NHK saved articles, favorites, backups and exploration runtime stay unchanged. Legacy clients retain their v1 protocol during rollout. Require existing tests, new chat-state and mic lifecycle tests, phone-only mocked UI screenshots, real OpenAI multi-turn/ASR/transport probe and production proxy smoke before final acceptance. Do not claim human-language quality or physical-device validation from mock or generated-audio tests.
