# 周喵瑜横抱古琴：提交给 Claude 的契约建议

本批完成周喵瑜的低吴冠。横抱古琴仍未完成，产品继续使用现有单手 `qin`。这份文件只提出引擎接口建议，没有新增实际挂点、类型或姿势，也不把古琴计入本批已完成的专属部件。

## 当前具体限制

现有 `PartBuilder` 返回的 weapon 默认挂 `handR`，其 `userData.offhand` 只能把第二个独立物体挂到左掌。姿势随后分别驱动两手；部件内部转动琴身可让 idle 单手姿势横置，仍不能保证两手在蓄力/演奏时支撑同一个刚体。把琴拆成两半或挂两把琴会产生两件独立乐器。`PartCtx` 也没有关节回调，无法从部件函数控制手臂。

因此需 Claude 在骨架/挂接/姿势侧提供明确支持，Codex 再按批准接口制作琴身。接口变更范围在本批授权之外，不在艺术部件里模拟或修改引擎。

## 最小方案

| 建议字段或挂点 | 建议含义 | 当前状态 |
| --- | --- | --- |
| 类型化 `userData.mountSocket: 'handR' \| 'torso'` | 默认兼容原 weapon；琴使用 torso 挂接 | 待 Claude 决定并实现 |
| `instrumentBone` | torso 下承载完整琴身的真实骨，参与正常 bake 与蒙皮 | 尚不存在 |
| 类型化 `userData.instrumentPose: 'qin'` | 让 pose 映射明确选用抱琴/拨弦分支 | 待 Claude 决定并实现 |
| 琴的局部握位 `gripR / gripL` | 各给局部 position/quaternion，之后可支持专用 FK 或 IK | 可作为后续扩展 |

初版可先用固定的胸前琴身位置和琴专用肩/肘/掌 FK：左掌托底，右掌拨弦；idle、windup、strike 三种姿势保持手在同一琴体上，其余十一姿势显式定义持琴策略。继续使用现有 `WeaponKind='qin'` 与 `HERO_PARTS[wu_zhoumiaoyu].weapon`，无需改英雄数据。返回根保持单位变换，琴身和所有饰物使用 Toon/outline 缓存，在装配时建立对象。

引擎应让这一路与 handR/offhand 默认路径兼容，并使正常 bake、骨索引、实际 actor 装配和截图路径都读取同一挂点/姿势描述；不另开只供审图的琴身位置。

## 接口落地后的验收

- 用真实 `buildCat3D(look,id)` 和 actor 验证完整琴体只挂一次、两手没有第二件独立琴。
- idle/windup/strike 原生约190px及真实十猫战斗中，两掌支撑/拨弦位置可读，琴体不穿头，不遮挡动态眼鼻口。
- 全14姿势与t=0～8的有限动画采样核对实际骨/蒙皮顶点、完整三角颅骨相交和FRAME裁幅；逐眼/当前嘴表面采样ID检查回归。
- 显式覆盖全部89个look/id，其他单位默认 weapon/offhand装配和烘焙字节保持一致；部件≤24逻辑网格、分段≤24、没有每帧对象分配。

这些是后续琴体任务的验收建议，当前文件不声称已经通过。其余已完成的UR部件和后续队列继续推进，不等待琴接口落地。
